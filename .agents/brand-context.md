# Brand Context

> 本文整理已讨论的产品定位，供命名使用；尚未确认的品牌偏好明确标注为工作假设，不代表已决定的产品承诺。

## Brand
- **Name**: 用户已确定「电波 / Dianbo」为名称；品牌与主产品的命名层级正在讨论。「电波系」用于单独产品名称仍在评估，尚未确定。此决定不代表商标、域名等权利核查已完成，也不代表重命名现有 AU05 插件或 DSH。
- **Name Origin**: 用户明确取意于「电波系」的性格特征，而非以物理无线通信作为核心释义。
- **Category**: 连接第三方 AI 硬件、AI 软件与 Agent Harness 的跨设备、跨平台交互联动平台。
- **Description**: 用户明确首要定位是打通他人的 AI 输入硬件（例如键盘麦）、AI 软件（例如语音输入与 LLM 文本优化）和 Agent Harness（例如 DeepSeek Harness）之间的交互。在各端支持的接口与授权范围内，连接硬件输入、语音或文本处理、目标会话操作及状态反馈。平台不以自行制造硬件、替代听写软件或重做 Harness 为核心，也不应被命名成泛桌面小工具、单纯快捷键映射器或另一个 AI 助手。设计及办公软件等连接仍可作为后续扩展，不是当前命名的首要落点。
- **Stage**: 产品探索与技术架构讨论阶段；已有 Windows AU05 DSH 插件，不代表独立通用平台已经实现。
- **Website**: 未提供。

## Audience
- **Primary Audience**: 使用多个 AI 和专业桌面软件的个人用户；希望扩展设备软件生态的硬件厂商；未来的适配器开发者。
- **Key Problem**: 不同品牌硬件、软件及 Agent 能力分散，控制方式和状态反馈不统一，跨工具连接需要重复适配。
- **Their Language**: 跨设备、跨平台、跨软件；打通能力；通用核心；独立平台；硬件和软件适配。

## Positioning
- **Differentiation**: 独立于单一硬件品牌和单一 Agent 宿主；强调能力适配、权限边界、动作路由和真实反馈，而不只是快捷键映射。
- **Competitors**: VibeWand（Agent 与硬件控制）；OpenDeck（多设备插件宿主）；Bitfocus Companion（设备和软件控制与反馈）。参照对象并不等于所有功能完全重合。
- **Market Position**: 专业工具与平台基础设施方向；具体定价和高低端定位未定。

## Brand Personality
- **Personality Words**: 工作假设：可靠、开放、克制、协作、可扩展。
- **Tone**: 工作假设：专业但不生硬，避免夸大效果和泛化 AI 宣传。
- **Voice Admires**: 用户未指定。

## Values & Mission
- **Core Values**: 命名工作假设：跨品牌兼容、用户控制、本地优先、能力与状态真实、持续可维护。
- **Mission**: 工作表述：让不同设备与软件的能力可以在用户授权下共同工作。

## Goals
- **Primary Goal**: 用户希望探索独立的跨设备、跨平台通用中间件；12 个月交付、收入及发布时间尚未确定。
- **Key Metrics**: 未设定；此前讨论中的验证阈值属于建议，不是用户已确认的目标。

## Naming Constraints
- 名称不绑定 AU05、DSH、单一 Agent、语音输入、手柄或某种编程语言。
- 三种风格的并行命名探索已完成；用户随后确定名称为「电波 / Dianbo」。不继续将其视为待定候选；「电波系」作为产品名的提议与品牌／产品层级仍待确认。
- 上一轮「桥序、协弦、共枢、承联、络序」及其英文组合整体被用户否定；不沿用架构术语堆砌、牵强拼词和先有名称后硬编寓意的方向。
- 先看读音、拼写、记忆和真实产品感，不强求名称解释连接、协作或完整架构；同时避免让人误以为是独立大模型、特定硬件或仅有快捷键的工具。
- 名称创意确认不等于权利清理通过；未穷尽的商标、公司名称、应用商店及包名等仍需核查。
