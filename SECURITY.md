# Security policy / 安全说明

The 0.5 development plugin implements real HID writes, current-session operations and opt-in microphone transcription. It is **not a production-certified driver** and has no supported binary release. Earlier mock/read-only tools remain separate historical paths; their “no writes / no session actions” guarantees must not be applied to the product Connect button.

0.5 开发版已实现真实设备写入、当前会话操作及显式启用的语音转写，但尚未完成全部真机验收。点击“连接设备”允许在线模式、心跳及受限灯控；关闭灯光开关不等于只读。不用管理员权限运行，也不要把 DSH 或历史 loopback 服务暴露到公网。

- Device access is explicit, vendor-only and owned by one bounded Host process; no arbitrary report, shell command, firmware update or global keyboard endpoint is exposed. No background reconnect.
- Session actions require the current unique, focused binding. Changed sessions, approvals, input ownership or focus invalidate old gestures. Approval is one-time only; never permanent permission or unattended blanket approval.
- Voice is off by default. In DSH mode, microphone permission is separate from Connect; audio uses the configured DSH speech service only while its recording context remains valid. Provider configuration determines local/remote processing, and draft insertion never submits a message.
- Optional Windows mode is a separate, explicit system-voice request, not DSH audio capture. Only a fresh single-use physical K1 press in a focused local desktop composer may request the fixed Win+H shortcut. Host validates owner/generation/context/age and cancellation; the native helper checks exact foreground DSH image, stable window/PID, editable nonpassword focus, modifiers and deadline before sending the constant keys. No arbitrary key/command/path endpoint or focus stealing is provided. Browser/remote clients cannot request this mode through the supported UI.
- Windows voice typing may immediately listen and uses Microsoft's online speech service; system permissions/network apply. The plugin cannot inspect system transcripts or guarantee draft-conflict recovery, panel activation, or stopping OS listening on disconnect. Stop it manually in the system panel before changing applications. Cancellation is best-effort before fixed SendInput commit; foreground or key-state checks cannot be atomic with the final OS input insertion.
- Optional Bageshuo cross-application K1 dictation is a narrowly scoped exception to the DSH foreground requirement: default off, local Windows desktop Direct mode only, enabled third-party voice with the Bageshuo observer, an independent cross-application context, and a fresh single-use physical K1 ticket. Only the fixed RightAlt tap is permitted; K2/K3/wheel and other voice modes keep their original scope. Native validation still pins the current foreground window/PID and nonpassword editable focus, checks modifiers and expiry, and never steals focus. Check-to-SendInput races cannot be eliminated. No global keyboard listener, arbitrary command/key stream or transcript/clipboard reader is added.
- Bageshuo capture lamps use read-only CoreAudio metadata for the bound target, not key counts or successful shortcut submission. Unknown/stale capture revokes the recording indication; app restart does not silently rebind. Turning off cross-application control/lights, disconnecting or exiting DSH does not guarantee stopping Bageshuo capture. Keep the desktop client/Host running for delivery; background throttling can delay or expire physical gestures. This new cross-application path is not yet physically validated.
- Lamp snapshot/readback and restore may fail. An OS write success is not evidence of physical appearance or persistent recovery. Do not rely on lamps as the sole indicator of an approval or running operation.
- Plugin code runs with the DSH Host's privileges. Owner-only RPC validation is not an isolation boundary against malicious local plugins or a compromised browser client.

Do not put tokens, recordings, personal session IDs, request keys, raw HID reports, device serials, private conversations or approval contents in public issues. Use GitHub private vulnerability reporting if available; otherwise contact the repository owner privately before sharing exploit details. No separate security email address has been established.

See the [current product guide](<docs/product-guide.md>). The [original threat model](<docs/security.md>) describes the earlier mock/bridge architecture and is retained for historical context, not as a certification of the current implementation. This project does not bypass DeepSeek Harness authorization or sandbox controls.
