# AU05 0.6.0-dev.4 快速使用

本地修正版，不是全部模式均已完成验收的稳定版。**0.6.0-dev.4 只做一件事：适配 DSH 0.2.3 把 `uiSession.sessionStatus` 拆成独立 Cordis 服务后的注入要求**，否则客户端插件在 `apply` 阶段抛 `cannot get property "uiSession.sessionStatus" without inject`，插件页显示“本页面的插件未能完成同步”，面板与悬浮层整体不出现。本版未做实机验收。

## 本版修正

- DSH 0.2.3 起 `uiSession.sessionStatus` 是独立 Cordis 服务，`@abworks/dsh-plugin-au05` 与 `@abworks/dsh-studio-hook` 的客户端入口都在运行时 `inject` 里单独声明它；否则 `apply` 抛 `cannot get property "uiSession.sessionStatus" without inject`，插件页显示“本页面的插件未能完成同步”，面板与悬浮层整体不出现。
- 这条是硬依赖：DSH 0.2.3 之前的版本没有该服务，本版会保持未激活。需要在 0.2.1 系列上用 AU05 时留用 `0.6.0-dev.3`。
- 认证后先发 SoftwareOnline／心跳，再核对本体连接状态，避免旧初始化顺序阻断灯控。
- 原始快照首次未取得时，仅首次真实 K1 录音请求可触发一次有界恢复；闲置不自动重试。原始配置未严格匹配前仍不写目标灯态，不放宽解析或恢复要求。
- 恢复期间已松手或关闭 K1 时，不补发迟到的 K1 On；不丢弃其他任务灯变化。
- 当前 K1 灯控仍是显式、每次连接启用的实验选项；不改语音流程、K2/K3、旋钮或其他灯态语义。旧开发包保留，不冒充包含本次修正。

## 安装与更新

要求 Windows 本机 DSH、Node.js 22/24、PowerShell 7。解压 ZIP，在 **DSH → 插件 → 添加插件** 选择目录，按管理器提示重新加载组件并刷新现有 DSH 页面。不要另开 Web 服务；磁盘版本不代表当前 GUI 已加载。

- 直连目录：`packages/dsh-plugin`，包名 `@abworks/dsh-plugin-au05`。
- Studio 还需目录 `packages/dsh-studio-hook`，与直连包版本须匹配。
- 可选 Studio 输入生产者目录：`StudioPlugin/com.abworks.dshinput.ulanziPlugin`。官方格式、自包含，含 MIT ws 运行时，不含配对密钥、私有 SDK、CLI 或固件。

两种模式在同一 Host 内互斥；互斥不能检测或强关外部 Studio。不会自动安装、发布、录音、回答审批或修改个人 Studio 配置。

## 直连与 K1

> 当前源码优先：K1 录音指示灯默认启用，独立实验开关已移除；只需启用语音与灯光反馈，重连无需另行开启 K1。下列三开关步骤仅描述旧 dev.3 打包基线。

1. 从托盘正常退出 Studio；停止 DSH 设置里的 Studio 跟随。唤醒 AU05，打开右上角 AU05 并手动连接。
2. 选择 **DSH 内置语音**，保留自己明确选定的麦克风。确认 **启用语音、灯光反馈、实验性 K1** 三个开关均 On。
3. 界面实验开关当前仍叫“实验性 K1 录音灯配置（未验证实体灯）”；这是保留的旧 UI 文案，本版没有借打包修改功能或默认值。新的单轮实体通过证据与更广泛稳定性分开记录。
4. 聚焦当前会话输入框，长按 K1 录音、松开转写；不自动发送。只有实际 recording、非准备中且焦点有效才请求 K1 呼吸。结束／取消／错误请求 K1 Off。
5. **每次断开、重新连接或重载后，实验性 K1 会复位为 Off，需明确重新开启。** 它不持久化。语音模式和麦克风选择的保存不等于已录音，也不会自行打开麦克风。

K2 发送草稿／当前可回答审批允许一次；K3 拒绝当前审批／取消运行；旋钮保持已选择的会话切换或滚动模式。只接收前台唯一会话的新鲜输入。

`written` 只表示系统接受写入；`verified` 表示配置回读一致，不等于物理灯可见。原设置读不到不能绕过快照保护；关闭灯光仍保留设备在线／心跳，不是只读模式。第三方快捷键请求不代表实际录音，第三方录音灯没有因本轮内置语音通过而自动完成。

## Studio：原有任务跟随与三键桥

断开直连，正常打开官方 Studio，选择唯一主会话后，在 **DSH 设置 → AU05 / Studio** 明确开始跟随。设置页关闭不等于停止；换会话、绑定变化、卸载或 8 秒租约失效会停止，不自动重绑。

转发真实用户消息、工具开始／结果和回合结束，以 `dsh` 身份经已核验 CLI 发送。只投影同会话、可回答且仍有公开回答函数的真实审批；不传审批内容，不自动回答。CLI 成功不是实体灯确认，停止不伪造 idle／Stop，也不承诺删除 Studio 队列。Studio 任务接口仍没有已证实的 K1 控灯入口。

三键桥先监听捕获，再明确授权：在自己安装的插件服务旁私密保存配对配置，正常重启这个自己的服务；在自己选定的 Studio 配置里放置 K1/K2/K3/Knob 动作，读取最近 8 秒的真实候选 ActionID／key，明确确认后才接收新的上下文与新按键。manifest 动作 UUID 不是实例 ActionID，不能猜填或重放发现按键。

配对含三个独立的 256 位短期密钥，只在明确读取的本地视图显示；停止／重连后需重新配对。不要把配置写进仓库、个人配置档、聊天、日志、URL 或截图。桥仅监听 `127.0.0.1`、固定非浏览器 Origin，不接受 `null` Origin。历史 120 秒受控试验已收到 K1/K2/K3/旋钮的真实回调，但未授权这些试验按键执行 DSH 操作；不能把回调通过扩大为完整 Studio 动作、双方向旋转或真实审批专项通过。

## 重启／重连验收与构建

先正常断开设备，再正常退出并重新打开 DSH，不强杀进程；保持 Studio 退出。回到本会话，手动连接，核对加载版本及当前修正源、内置语音／麦克风和三个开关，再做一次用户手动正常录音。记录人类视觉与同轮 On／Off 回读；不自动开麦、不做空白灯效对照。未取得实际结果前，重启稳定性保持“待确认”。

打包前完整回归为 **480/480 通过，0 跳过**，含当前安装 DSH `0.2.1-rc.5` 的 loader／React／renderer 离线隔离夹具；不是重启后的实体验收。

构建命令：`npm test`、`npm run check`、`npm run build:plugin`、`npm run pack:plugins`。只生成本地 ZIP、两个 TGZ 和 SHA256 清单，不发布、不安装、不连接设备。清单的整体 `hardwareTested: false` 是保守边界，不否定内置 K1 已有的单轮实体通过，也不表示全部其他模式均已通过。
