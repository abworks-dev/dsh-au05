# 中文只读观察器使用说明

适用插件版本：`0.3.0`。需要 Windows、PowerShell 7 和 Node.js 22 或 24；本机已安装 DSH，并通过官方插件管理器安装/更新本仓库的插件目录。无需管理员权限，也不需要新 npm 运行时依赖。启动器优先查找 `node`，并可回退到本机 DSH 安装中已知固定路径的 Node；该回退不保证兼容其他安装布局。启动脚本遵守系统 PowerShell 执行策略，不绕过组织策略；若脚本被策略阻止，应先按本地管理要求放行。

## 两个界面的职责

- **本机中文启动器**：显式开始一次限时采集、停止、手动重新采集，显示状态与事件报告计数。
- **DSH 中文面板**：只读显示绑定会话的状态，以及通过认证 GET 接收的 AU05 事件；不能启动本机进程，也不能停止设备采集。

设备写入与会话控制始终关闭：没有灯控、初始化、心跳写入、按键注入、发送、中断或审批接口。窗口打开、插件挂载、视图返回都不会自动启动设备读取。

## 日常使用

1. 双击仓库根目录的 [启动只读观察器.cmd](../启动只读观察器.cmd)，或在仓库运行 `npm run observer:gui`。
2. 窗口最初显示“未启动”，此时没有 Node 观察桥、网络轮询或 HID 采集。点击“开始”才运行固定的本机只读采集程序。
3. 点击“复制连接令牌”，在 DSH 会话输入区下方的 AU05 中文面板粘贴，然后点击“连接”。这是首次配对步骤；不会自动读取剪贴板或把口令加入 URL。
4. 采集中可以看到最近事件及按下/松开/左右脉冲计数。**这些是事件报告计数，不代表物理操作次数，也不是本轮新的硬件准确率认证。**
5. 每次最多采集 120 秒或 10000 份报告；到期不会自动重试、延长或重新打开设备。
6. 再次采集时，在本机启动器点击“重启”（或停止后再“开始”）；在 DSH 点击“手动重连”。这两步分别控制采集和浏览器观察，均需要人工操作。
7. 本机点击“停止”结束采集；关闭启动器也会清理本窗口启动的观察桥和子采集进程。DSH 的“断开观察”**只断开浏览器连接，不停止本机采集**。

打开整个启动器窗口期间，连接令牌仅生成一次，因此手动重启采集不需要再次粘贴。DSH 只在收到合法的只读数据后保留该令牌于当前插件实例内存，以供手动重新连接；主动断开、插件卸载或页面重载会清除该记忆。关闭并重新打开启动器会生成新令牌，必须重新配对。

## 状态如何理解

| 状态 | 含义与下一步 |
|---|---|
| 未启动 / 未连接 | 尚未显式开始本机采集，或尚未连接 DSH 观察流；二者不是同一开关。 |
| 启动中 / 连接中 | 正在启动固定采集进程，或等待认证观察连接；不自动重试。 |
| 采集中 | 本次采集已打开通过身份核验的只读设备句柄；不表示每个动作都一定收到。 |
| 到期结束 / 采集结束 | 达到本次上限或采集已结束；计数保留。要再次采集，需要显式重启。 |
| 设备断开 / 未检测到设备 | 没有可用设备，或采集端报告设备/读取失败；界面不是拔插可靠性的证明。 |
| 连接中断 / 连接失败 | 观察流关闭或认证/传输出错；不自动恢复。先检查本机启动器，再手动连接。 |
| 已停止 | 本机采集已停止；不会自动启动下一轮。 |

终态原因也保存在只读 health/snapshot 中；重新连接一个已经到期的观察桥，只会看到旧轮次的终态与计数，**不会启动新采集**。

## 安全与退出

- 观察桥固定绑定 `127.0.0.1:17376`；已有进程占用端口时启动失败，不强杀、接管或探测其他进程。启动器必须先从自己启动的 Node 标准输出收到严格匹配、完整且有长度上限的绑定成功记录，才发送带令牌的本机 health 请求；单靠端口有响应不能算就绪。10 秒内未就绪、输出异常或提前结束会停止所属进程，不自动重试。
- HTTP 只有认证 GET health/events；没有开始、停止、重启、会话控制或设备写入的 HTTP 路由。本机启动器通过它自己创建的子进程 stdin 发送固定停止消息，管道关闭也会停止。
- 停止先异步请求正常关闭，最多等待 5 秒，必要时仅终止本窗口拥有的进程树；不按进程名或端口杀其他程序。清理未确认时不自动启动替代采集。
- 启动器使用随机 256 位内存令牌，通过子进程环境传入桥，不写配置/磁盘、不输出日志，也不传给 HID 采集子进程。独立 CLI 原有的用户私有临时令牌方式仍可用。
- 只有手动点复制才写剪贴板。**系统剪贴板及剪贴板管理器可能保留口令**；请仅粘贴到可信本机 DSH 面板，用完可自行覆盖剪贴板。程序不擅自读取或清空其他剪贴板内容。
- 原有 Studio/设备快捷键可能仍响应物理按键。本项目不修改预设，也不保证其他软件零写入。首次操作先把焦点放在安全窗口，避免设备既有映射造成意外输入。

## 离线自测与验证边界

```text
npm run observer:gui:selftest
npm test
npm run check
```

`observer:gui:selftest` 在 UI 程序集加载、令牌生成、进程启动和网络访问之前返回，仅验证解析、布局数据及脱敏状态转换；不会显示窗口或访问设备。完整测试中的观察桥使用合成事件，不启动采集子进程。

当前版本的测试和 GUI 检查结果另记在 [只读验证记录](readonly-validation.md)。旧版本已经完成的六类真机输入记录，不自动成为新版启动/停止/重启和设备异常的实测记录。新版硬件轮次、长期稳定性、设备重连、灯控、完整卸载和任何会话控制都要独立验收。
