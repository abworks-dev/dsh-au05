# K2 / K3 按键短亮

## 使用

在 AU05 设备设置中开启「K2 / K3 按键短亮」。默认关闭，仅直连模式支持；总开关「灯光反馈」关闭时不生效。

K2、K3 收到新的实体按下事件时，可短暂常亮约 250 毫秒，然后恢复按下前的灯光字段。短亮只确认按键输入，不表示补齐、发送、批准、拒绝或停止已经成功。K1 的录音灯和语音逻辑不变。示意图输入高亮仍独立工作。

## 优先级和限制

- 同一通道的原有状态灯优先；目标按键已有常亮或呼吸状态时，不叠加短亮。其他通道可保留各自状态，例如 K2 审批灯不妨碍空闲 K3 的反馈。短亮过程中收到新状态请求时，先恢复临时字段，再按原事务处理。
- 仅在已读取可靠当前灯光配置、设备处于逐通道模式（mode 2）、目标通道原为关闭且亮度非零时反馈。不为短亮改变全局模式，也不强行提高零亮度。
- 使用接管后已确认的当前配置；空闲接管也先完成快照与四灯关闭的配置回读。配置不可确认或按下事件已过期（500 毫秒）时跳过，不在数秒后补闪。不为按下额外启动 GET，只有建立可信基线后仍在新鲜窗口内的事件可反馈；不取消无关联 ID 的 GET，以免旧响应污染后续读取。连续快速按键可能合并或跳过，并不保证逐次闪烁。
- 关闭设置通过下一次串行轮询撤销，须等待正在进行的请求；不是同步硬件关闭。轮询失败沿用断开与租约回收保护。
- 临时修改只限目标通道的工作类型和常亮亮度，随后精确恢复；不修改 K1 或其他通道的记录。不把短亮当作新的任务状态或成功结果。
- 250 毫秒是本地计时目标，不是 USB 写入延迟或实体灯的硬实时保证。断开、停止或写入失败使用现有原配置恢复保护。
- 不支持 Studio 模式；Studio 的实体灯仍由 Studio 管理。

## 验证边界

自动化使用假 Host、假计时器和内存 HID 流，不连接设备或触发真实语音、审批、发送、停止。配置回读一致只说明配置，不证明实体灯外观；真实短亮时长和亮度仍需用户参与的实机验证。
