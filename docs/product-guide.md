# AU05 0.5 产品使用指南

适用版本：`0.5.0`。本文是当前实现的使用说明，**不是本轮真实 DSH GUI、麦克风或 AU05 硬件验收报告**。已安装组件显示“运行中”也不等于已经连接接收器、成功录音或验证灯态。

## 1. 准备与安装

- DSH Host 运行在 Windows，并可执行 PowerShell 7。接收器应插在 Host 电脑；浏览器麦克风则由打开 DSH 页面的浏览器请求授权。
- 通过 DSH 官方插件管理器添加 [插件目录](../packages/dsh-plugin/README.md) 所在的本机目录，启用插件包和对应组件；按 DSH 的版本兼容性提示操作。无需改写安装包、手工编辑 profile 或另起 Web 服务。
- 只连接一个目标接收器。检测不到设备、出现多个候选设备或身份核验失败时，不会任意选择一个继续。
- 先正常关闭或断开 AU05 Studio、旧只读采集器及其他占用同一接收器的程序。插件使用独占设备句柄；Studio 与 DSH 不能同时控制同一接收器。不要通过反复连接或强制抢占解决竞争。

0.5 已由 Host 直接管理设备连接，**不需要旧只读启动器、HTTP 观察桥或连接令牌**。旧流程与产品流程不要混用。

## 2. 连接与断开

1. 进入 DSH 会话界面，找到右上角“AU05”胶囊，点击展开“AU05 设备”面板。
2. 确认会话状态。按键只作用于当前唯一主会话；没有唯一活动会话时，不猜测其他目标。
3. 决定是否需要灯光反馈。该选项初始开启。**产品连接始终需要软件在线与心跳等设备写入；取消灯光勾选不等于只读。若不允许设备写入，不要点击连接。**
4. 默认点击“连接设备”才请求 Host 启动连接。可选勾选“启动时自动连接设备”：初始关闭，改变勾选只保存偏好、不立即连接；下次插件加载后至多尝试一次，前提是本机 Windows DSH 桌面且 RPC 可用。
5. 自动连接不是后台重连：面板展开、组件重绘、服务重新出现、失败、设备断开或用户点击断开，都不会重复尝试。不可用时提示并等待手动连接；没有定时重试或 Windows 登录自启动。
6. 用完点击“断开设备”。仅收起面板或按 Escape 不会断开。刷新／重新启用插件属于新的加载，已保存自动连接时可再次尝试一次；不希望如此，请先关闭自动连接。自动连接同样会进入可写产品模式，务必先退出 Studio。

“断开设备”会取消插件管理的 DSH 录音、作废旧输入并请求 Host 释放设备。Windows 系统听写不由插件管理，已打开时仍需在系统面板手动结束。若断开请求未获确认，面板会提示 Host 在租期结束后释放；不能把这条提示当成已经完成的硬件释放证明。插件禁用／卸载也会清理连接。

## 3. 按键与会话边界

| 设备动作 | 当前行为 |
|---|---|
| 按键1按下 | 已启用语音时：DSH 内置模式开始录音；Windows 原生模式请求系统听写；第三方模式发送预设／自定义快捷键的一次完整点按。外部模式仅支持本机 DSH 桌面的唯一输入框已聚焦时触发。 |
| 按键1松开 | DSH 停止录音并转写到原草稿；Windows／第三方不执行操作。Windows 在系统面板结束；Typeless 再新按 K1 结束，若失焦／不响应则在 Typeless 内手动停止。均不自动发送消息。 |
| 按键2 | 无待处理交互时，调用当前输入的发送动作；若有当前可回答审批，仅允许本次请求一次。 |
| 按键3 | 若有当前可回答审批，拒绝它；否则取消当前正在运行的任务。 |
| 旋钮左转／右转 | 新偏好默认“区域切换”：滚动高亮区域；选择题选项只移动焦点、不自动提交。保留切换会话、上下滚动、整屏滚动和禁用旋转，已有偏好不覆盖。 |
| 旋钮按下 | “区域切换”下循环选择可用的会话列表、对话、输入框和选择题选项；旧模式仍聚焦唯一输入，不模拟全局键盘输入。 |

“允许一次”不是允许整个会话、不是永久信任，也不代表未来审批自动获准。同一审批的重复按下不会反复回答；其他待处理交互需要在 DSH 界面完成。

窗口失焦、页面隐藏、当前会话切换或审批上下文变化时，旧手势和录音作废。一直按住某键跨会话不会在新会话触发新操作，需先松开再重新按下。设备事件还会检查连接代次、顺序和时效；积压或上下文不符时宁可丢弃，不补执行。

### 旋钮行为

- **区域切换（新偏好默认）**：按下旋钮依次选择可用区域。滚动时，**鼠标须停在高亮区域内**；本机 Windows DSH 桌面直连复用“上下滚动”的原生滚轮桥，左转 +120、右转 -120 wheel delta，交给系统与应用处理，不再执行每格 80 像素的自定义动画。不移动鼠标、不抢焦点，原生发送失败不回退到 DOM 滚动。Studio／浏览器不注入系统滚轮，滚动区域不可用；选择题选项仍只移动焦点，由 K2 单独确认。切区、清除高亮、元素替换、窗口失焦或会话／待处理问题变化会作废旧请求；需要时重新按下旋钮选区。
- **切换会话**：左转上一个、右转下一个，仅限当前工作区，不跨越列表边界。
- **上下滚动**：本机 Windows DSH 桌面直连下，左转发出系统滚轮 +120、右转 -120，单位是 wheel delta，不是像素；交给系统与应用处理滚动。需要 DSH 在前台且鼠标停在当前会话内容区，松开 Ctrl／Shift／Alt／Win。Studio／浏览器不注入系统滚轮，请使用 Studio 自身的原生滚动配置。
- **整屏滚动**：按当前内容区高度的 80% 移动，至少 120 像素；不是切换会话，也不会加载全部历史。
- **禁用旋转**：转动不执行操作；旋钮按下仍按原行为聚焦当前草稿。

临时定位区域滚动卡顿：在“区域切换”下展开“设备设置 → 高级设置 → 滚动诊断”，点击“采样 5 秒”，只转动旋钮，结束后手动复制只读 JSON。采样最多保留 240 条本地记录，仅含数值时间、位置与固定原因码；浏览器支持时，额外记录这 5 秒内的长任务／长动画帧起点、耗时与阻塞时长，不读取脚本名、URL 或任务归属。不含聊天文本、会话标识、音频或截图，不上传、不持久保存；重新采样覆盖旧记录。采样结束本身不会停止正在运行的滚动；模式变化或断开会结束采样并保留结果。原生模式不再产生自定义动画的逐帧位置记录；输入 accepted 只表示事件通过前端校验，不代表原生发送或实际位移已确认。实体手感仍待重载后人工验证，诊断仅用于取证，不代表修复完成。

选择会记住，改变设置会作废旧事件。“上下滚动／整屏滚动”通过官方 `conversation.input.dock` 会话插槽中的隐藏锚点，在自身祖先范围识别唯一可见内容区并核对会话及 owner。整屏滚动仍使用局部 DOM 平滑滚动；“上下滚动”与“区域切换”的滚动区域共用系统滚轮桥，每个真实旋转票据最多消费一次，500 ms 过期，不重试、不回退到 DOM、不移动鼠标或抢焦点。桥因超时或取消关闭后，下一次实体旋转只触发恢复，不执行该格；等待启动后再次旋转。尚未发送的单条失效请求只丢弃自身，不关闭桥。若持续提示未确认，请切换旋钮行为后重新启用上下滚动，或手动断开重连；旧事件不会补执行。

以下限制同时适用于“上下滚动”和“区域切换”的原生滚轮：发送前复查指定 DSH 可执行文件、前台窗口、鼠标位于该窗口客户区及修饰键。它不能原子绑定网页中的会话区域：切窗／移鼠与异步发送之间仍有竞态，因此不要在转动过程中快速移鼠到其他控件。本实现未承诺严格隔离到原会话，也未验收实机手感、持续输出自动跟随／折叠动画；操作系统注入事件与设备原生硬件事件身份不同。

## 4. 四种可选语音：不自动发送

面板提供 **DSH 内置／Windows 原生／应用预设／自定义快捷键**。应用预设含 Typeless 与网易叭哥说；自定义是单独模式，不藏在预设列表里。首次选择 DSH，四种模式默认关闭，分别记住启用选择。返回曾启用的模式可恢复勾选，但不会开始录音、弹出系统听写或发送快捷键。已有冲突转写文本时，先手动处理并清除保留文本，避免切换时丢失。

### 偏好保存与权限边界

- 仅保存模式、各模式启用偏好、DSH 麦克风选择、应用预设、单独的受限自定义快捷键、旋钮行为和启动自动连接偏好；不保存音频、转写文字、会话、实际设备连接状态或权限凭据。v1／v2 偏好兼容迁移到 v3；旧版已选自定义时迁移至独立自定义模式并保留原快捷键与启用偏好，预设与自定义不会互相覆盖。缺失的开关默认关闭，旋钮行为默认区域切换，不新增连接或录音动作。
- 偏好保存在当前浏览器／桌面客户端存储环境、当前页面来源的本地存储中。相同环境和来源下刷新页面或重启应用可恢复；不同浏览器配置、桌面与普通浏览器、不同页面来源（含不同端口）不保证共享，清除站点数据会重置。不是 DSH Host 全局设置或跨设备同步。
- 存储被禁用、不可访问或写入失败时，本次页面仍可使用，但不能承诺刷新／重启后保留；留意未保存提示。
- **“已启用”是用户偏好，不等于已经获准、麦克风就绪或正在录音。** 浏览器／Windows 权限独立管理；恢复偏好、选择模式、展开面板、刷新麦克风列表都不会打开麦克风。DSH 仍需新的 K1 按下才开始录音；用户主动勾选启用时则可能为权限检查短暂打开音频流并立即关闭，不录制、不转写。Windows 和第三方仍需新的 K1 请求外部语音。语音偏好恢复不连接 AU05；启动自动连接为独立的默认关闭选项。

### DSH 内置

1. 在 DSH 中配置可用的语音转写提供商；可从“配置语音”入口打开设置。
2. 在面板的麦克风下拉框查看并选择浏览器可见的音频输入；“刷新麦克风列表”只重新枚举，不录音、不为显示设备名称而请求权限。尚未授权时，名称或列表可能不完整。
3. 首次尚无选定输入时，优先匹配可识别的 AU05 麦克风；没有 AU05 时可使用系统默认输入，识别到实际物理输入后固定并保存。自动选定或手动选定后，不因发现 AU05 或刷新列表而覆盖。保存的输入已拔出／不可用时提示用户选择，**不自动替换为其他麦克风**；用户明确选择“系统默认麦克风（跟随系统）”则按其名称跟随系统。重新插入或权限变化后可刷新列表再确认；浏览器设备标识变化时可能需要重新选择。
4. 明确启用 DSH 语音：这一主动操作可能请求浏览器授权并短暂打开音频流用于权限检查，随即关闭；不启动录制或转写。首次尚未识别 AU05 时，权限检查可能先使用系统默认输入，随后按可见设备名称优先选定 AU05。启用偏好、麦克风选择与浏览器麦克风权限互不替代；连接设备本身不授予权限。确认提供商与处理位置，云端提供商会接收录音。
5. 在当前输入视图按住 K1 说话；此时打开所选麦克风并开始录音，必要时由浏览器询问授权。恢复偏好本身不做上述权限检查。松开后转写并安全插入原草稿。检查后另行发送。

权限被拒绝、所选麦克风不可用、提供商缺失或转写失败时不发送草稿，也不偷偷换用其他麦克风。失焦、切换会话会作废旧录音／转写。原草稿变化时，转写文字保留在面板供手动复制，不覆盖新草稿。

2026-10-29 验证：完整本地回归 **203/203 通过、0 跳过**，包含实际已安装 DSH loader／React 的隔离离线 fixture，以及偏好恢复、模式分别记忆、精确麦克风约束、掉线与异步竞态测试。现有 DSH 桌面中文面板已显示保存提示和麦克风下拉框；仅刷新列表即识别并选中本机 AU05。切换 Windows 模式后不显示 DSH 麦克风选择；返回 DSH 并刷新列表后仍选中 AU05。检查结束保持 DSH 模式、语音未勾选、设备未连接，未主动请求录音、转写或 Win+H。应用完整退出重启、实际音频来源及两种语音端到端转写仍需另行实测；不能把离线测试或界面选择当作音频采集已验收。

### Windows 原生（Win+H）

1. 仅支持接收器与 Host 所在的 **本机 Windows DSH 桌面版**；普通浏览器和远程网页不触发 Host 的系统快捷键。推荐 Windows 11，按系统能力及设置决定是否可用。
2. 选择 Windows 原生并明确启用（已有该模式启用偏好时可恢复勾选）。无需配置 DSH 转写提供商，插件不请求浏览器麦克风、不采集音频。**输入设备由 Windows 的声音／语音设置管理**；DSH 模式的麦克风下拉框不控制 Win+H，插件不提供虚假的 Windows 应用内麦克风选择。
3. 收起面板，手动聚焦当前 DSH 草稿输入框；或先按旋钮聚焦。**新按一次 K1** 请求 Windows 语音输入，松开 K1 不会结束听写。
4. Windows 面板出现后可能立即开始侦听。需要系统麦克风权限、在线语音及网络；音频可能发送至 Microsoft/Azure Speech。**在系统面板点击麦克风或使用系统“停止听写”命令结束**，检查草稿后另行发送。

系统模式通过 Host 固定的 Win+H 执行器请求，不提供任意按键、命令或路径接口。Host 校验真实新鲜 K1 手势、连接代次、唯一输入上下文与单次消费；原生执行器再次验证前台 DSH 可执行文件、同一窗口／进程、非密码可编辑焦点、时限及修饰键。不会替用户抢焦点。系统受限或焦点不符时显示中文错误，不降级为无条件全局快捷键。

“已请求 Windows 语音输入”只代表固定快捷键已提交，不证明系统面板出现、麦克风开启或转写成功。Windows 管理听写生命周期；插件无法读取／安全插入／恢复系统转写，不能承诺系统听写具有 DSH 模式的草稿冲突保护。切换模式、失焦、断开或卸载会取消尚未提交的请求，**不能撤销已提交的系统快捷键，也不能保证已开启的系统听写停止**。请先在系统面板结束听写，再切换应用或会话。

参考：[Microsoft 语音输入与开始／停止方式](https://support.microsoft.com/en-us/accessibility/windows/use-voice-typing-to-talk-instead-of-type-on-your-pc)、[SendInput 行为和限制](https://learn.microsoft.com/zh-cn/windows/win32/api/winuser/nf-winuser-sendinput)。本轮仅离线回归和编译，不自动触发 Win+H 或麦克风。

### Windows 收音观察修正（2026-11-03 源码）

- 在进程归属检查前排除 CoreAudio 明确处于未活动／过期状态的会话，避免旧跨进程会话返回 `AUDCLNT_S_NO_SINGLE_PROCESS`、PID 0 时把正常闲置误报为未知。活跃且归属不明的会话仍失败关闭。
- 微软签名校验之外，精确允许 Windows 实际安装路径 `System32/Speech_OneCore/common/SpeechRuntime.exe`；不按进程名或任意目录放宽信任。
- 本机只读元数据探测已由 `unknown` 恢复为 `idle`，147 项 Windows／Direct 客户端相关测试通过。未自动启动系统听写；真实收音→停止和实体 K1 呼吸／熄灭仍须现场验收，不能把此修复记为 Windows 实体灯已通过。
- 原生观察器已经运行时，先在系统面板结束听写，再断开并重新连接 AU05，以启动修复后的观察器。

### 叭哥说单击切换与采集灯（新增源码）

本节优先于下方旧通用说明；旧 dev.3 归档不包含本次新增。2026-11-03，Windows Direct／叭哥说 1.0.41.0 已由用户确认一轮“K1 单击启动 → 呼吸 → 再按 K1 停止 → 熄灭”，同连接保留的开／关灯配置均独立回读一致。此结论不包含长时间稳定性、跨应用重启自动恢复或 Studio 模式。

1. 先正常退出 Studio（含托盘），启动叭哥说并确认它的 RightAlt 为“单击开始／再次单击结束”，暂不开始录音。插件不安装或启动第三方应用。
2. 在本机 Windows DSH 的 Direct 面板选择“应用预设 → 网易叭哥说”，明确启用语音并连接 AU05。K1 录音指示灯默认启用，无独立开关，重连无需另行开启；启用叭哥说语音即自动只读观察实际采集状态。全局“灯光反馈”控制是否写灯；关闭语音或断开设备停止观察。

## 5. 灯光反馈与真实保证范围

任务灯按[官方 Codex／Claude 状态规则](https://docs.ulanzistudio.com/vibekey/faq/codex-claude-status.html)复刻，由 DSH 当前唯一主会话的真实状态驱动，不伪造 Codex Hook 事件，不改动用户的 Codex 配置或依赖 Studio 的 Hook 进程。以下都是插件请求的目标，不是对物理灯态的观察。

| 场景 | 目标（K1／K2／K3／旋钮） |
|---|---|
| Direct 待命／没有唯一主会话，灯光反馈开启 | 灭／灭／灭／灭；有效录音提示与可选实体按键短亮除外 |
| Direct 任务结束且无其他有效灯光提示 | 保持接管，请求四灯关闭，并回读确认 |
| 关闭灯光反馈 | 释放任务灯接管，恢复原配置；未接管时保留原样，不强制熄灯 |
| 任务运行且可请求中断 | 灭／灭／呼吸／常亮 |
| 等待当前会话的有效单次审批 | 灭／呼吸／呼吸（可拒绝）／灭 |
| 等待可回答的问题或计划评审 | 灭／呼吸／呼吸（需人工介入）／灭 |
| 问题已继续、任务仍运行 | 灭／灭／按可请求中断状态／常亮 |
| DSH 内置麦克风实际开始录音 | 仅 K1 请求呼吸；其他三灯仍由任务状态决定 |
| Windows／第三方快捷键已发送 | 不因此点亮 K1 或旋钮，不假装已知外部录音状态 |

- K2／K3 使用同一硬件呼吸参数；旋钮表示任务推进，使用常亮，不再以旋钮呼吸替代 K1。多条审批只形成确认状态，不按数量、节奏或呼吸次数叠加。
- `running` 与待处理交互在 DSH 中可以同时为真。等待审批或仍阻塞的问题时不点亮“正在推进”的旋钮；已继续的问题不再当作阻塞。审批已经回答但尚未从状态投影移除时，不重复提示，也不提前推断任务已恢复。
- 任务灯只看当前唯一绑定的主会话，不汇总后台其他会话。未处于有效跨应用模式时，窗口失焦仍跟随该会话的任务状态；有效跨应用模式下，失焦或页面隐藏会请求关闭 K2／K3／旋钮任务灯，回到 DSH 后按最新状态恢复，K1 实际采集提示不受此任务灯规则影响。仅保存跨应用偏好、但未处于已启用语音且已连接的本机 Direct 叭哥说模式时，不启用此例外。**K2／K3／旋钮操作仍要求前台聚焦和有效绑定**，灯亮不授权执行操作。
- K2 对问题／计划评审的提示表示“请在界面确认”，不自动生成答案；物理 K2 仍只支持已实现的单次审批。K3 的运行提示表示“可以请求中断”，不是 SDK 暴露了权威 `canCancel`，也不是已经取消；取消结果仍以 Host 反馈为准。
- K1 必须处于 DSH 实际录音阶段且麦克风准备已完成；授权中、获取设备中、仅恢复启用偏好、快捷键已提交均不算录音。物理 K1 指示灯此前未通过可见验收，本轮规则修正不等于该硬件问题已解决。
- 未指定亮度时沿用既有任务预设：K1 保留参数，其他通道工作时间为 `255`，不宣称单位或无限时长。显式应用亮度时改为官方单字段策略：仅改 K1/K2/K3 呼吸亮度及旋钮常亮亮度，不覆盖 live 工作时间、呼吸等级和另一亮度。Direct 连接且启用反馈时持续接管，待机及任务结束请求四灯关闭；有效录音与可选实体按键短亮仍可覆盖对应通道。仅关闭反馈、断开或正常退出时尽力恢复首次接管前的全局模式与四通道原始记录（包括工作时间、呼吸参数及亮度），不覆盖恢复基线。Studio 模式不改变其灯光管理。

- 灯光反馈初始开启。产品连接始终以可写 vendor HID 句柄进入软件在线模式并发送心跳，以支持主动输入与抑制设备原生快捷键重复。灯光开关只控制反馈目标，不切换句柄权限；关闭反馈时释放任务灯接管并恢复原配置，不停止其他设备协议写入。
- 接管灯态前读取并保存原状态；读取失败则不写目标灯态，输入仍可继续，面板提示未确认及唤醒后重连。USB 接收器可连接不代表无线设备已醒来或一定会返回设置查询。
- 工作灯控保持全局模式 `2`，按 `focus=0/1/2/3` 逐通道提交，帧间隔 80ms；显式亮度使用独立 type-only／brightness-only 帧，之后重新 GET 配置。不能把一次固定 `focus=0` 的提交当作四灯均已设置。
- Direct“高级设置”的亮度范围为 `0–20`、步长 `1`，按官方 AU05 滑块取值直接传递，不做百分比换算；首次未设置时预选 `2`，点击“应用亮度”前不新增 brightness。旧保存值 `21–255` 迁移为 `20`，合法 `0–20` 不改；`0` 是亮度值，不替代空闲四灯关闭目标、关闭灯光反馈或恢复原灯效。配置对齐与实体验收分开，见[亮度记录](<brightness-recovery.md#2026-11-04-按官方亮度逻辑对齐>)。
- `pending` 显示“待确认”；`written` 显示“已提交，未回读”，只表示写入已被操作系统接受；`verified` 显示“配置回读一致”，表示目标配置与设备返回字段一致；`mismatch` 显示“配置回读不一致”。`failed` 表示本次操作未确认完成，不把原状态读取失败误称为写入失败。
- 启用期间待机四灯关闭也须回读确认，不能把全零请求直接当成已熄灭。显式关闭反馈后的恢复单独区分“原配置已回读恢复”“恢复已提交但未回读”“恢复回读不一致”，只有完整原配置与 GET 一致才确认配置恢复。恢复过程中不保留过期的任务灯光圈；无可用配置回读时提示未知，不拿期望向量代替。此项为源码变更，空闲灭灯及退出恢复仍需用户实测。
- 关闭反馈不再等同于关闭设备全部灯光：未接管时保留原样，已接管时请求恢复原配置；未回读、不一致或失败保留相应提示。**配置回读一致也不证明物理灯已亮／已熄灭，更不等于人工可见灯态验收。**
- 正常停止时，尽力逐 focus 恢复本次修改前保存的全局模式及四通道记录，并发送软件离线。拔出设备、进程被强制终止或恢复写入失败时，不能保证恢复。

### 2026-10-29 focus 对照实测（仅配置层）

### Windows 桌面版刷新与浏览器认证

当前参考桌面版的 Windows 生产菜单没有启用普通 Reload 快捷键，`Ctrl+R` 无反应不代表插件无效。若需要刷新已登录的桌面窗口：让该窗口获得焦点，按 **F12** 打开开发者工具，选择 **Console**，手动输入唯一一行 `location.reload()` 并回车；页面恢复后再按 F12 收起工具。这只刷新当前页面，不退出 Host，不启动新服务，也不读取令牌。
