# DSH Studio Input (official-format plugin)

Input-only Studio action producer. It uses its own UUID `com.abworks.ulanzistudio.dshinput`, Studio's official loopback WebSocket port 3906, and the public SDK's full action-frame callback shapes. The adapter is minimal SDK-compatible code, **not the full official SDK**. It does not read DSH or other agents' history, open HID/microphones, install global hooks, inject keys, execute DSH actions, or answer approvals.

## Documented Studio entrypoint

The manifest now uses `service.js`, a thin CommonJS launcher for the unchanged tested `service.cjs`. The [pinned official manifest contract](https://github.com/UlanziTechnology/UlanziDeckPlugin-SDK/blob/550ab80c69285ecf259bd494a7fff767c14f0c0f/manifest.zh.md) explicitly documents `.js` loading with Node 20.12.2, not `.cjs`. This aligns the entry with the documented contract; it does **not** establish that the old suffix caused the absent SDK listener or that the corrected plugin has passed live loading. Previously delivered dev.2 archives are immutable and do not contain this subsequent source correction.

## Explicit setup — never automatic

1. Parent integration must explicitly enable its owner-only input bridge. `createStudioInputBridge().start({owner,sessionNonce,generation,epoch,bindings})` creates a dedicated ephemeral `127.0.0.1` listener. Only owner `poll()` renews its maximum eight-second lease.
2. The owner-only pairing UI obtains `pairing(owner)`. Provision this exact JSON as `bridge.json` **beside the installed plugin service**, with access restricted to the current OS user. The bundle never contains this file. It contains three independent 256-bit capability secrets (`leaseToken`, `eventToken`, `bindingToken`): do not paste it into logs, profiles, a URL, a screenshot, or ordinary status/event RPCs. The plugin reads only this one local file, not arbitrary paths. Stop/restart rotates the endpoint and secrets, requiring explicit re-pairing. After replacing this file, explicitly restart **only this own plugin service** so it reads the new pairing; it does not watch mutable configuration or restart Studio. No listener or plugin is installed/started by this source delivery.
3. Start with `bindings: []` for capture-only pairing: no key or knob event can execute. In Studio, manually place the DSH K1/K2/K3/Knob actions on desired ordinary action slots in the user's chosen profile. The own official-shaped `add`/`setactive` callbacks (or own action input callbacks) report only `{control,actionid,key}`; the manifest action UUID is **not** the per-instance `ActionID`. The owner-only UI reads `bridge.bindings(owner)` (at most four recently observed candidates), shows the choices, and requires explicit confirmation before `bridge.configure(owner, chosenBindings)`. Confirmation works only from empty bindings with no previously accepted input and candidates observed within eight seconds. It clears queued/pressed state, fences pre-confirmation timestamps and resets foreground context to null; a new owner poll must authorize future arrivals. The producer's next lease read safely picks up the confirmed bindings. A first discovery key press is never replayed. If no own callbacks arrive in the selected mode, stop: do not guess IDs or enumerate a saved profile. Explicit pre-known bindings remain supported for controlled integrations. There is no profile import/modification, global mapping, shortcut fallback, or assumption that every button is assignable.
4. Client eventpoll supplies an opaque context token. Every event captures that token **at acceptance**, not at later polling. Initial context is null. Client must reject null/changed context and recheck foreground, session identity, generation/epoch, age and current interactive approval before acting. Lost bridge/lease/foreground must cancel held Client actions.

## Hardware and mode truth

Prior Studio 3.4.8 hardware evidence verifies knob down/up and left/right through an explicitly bound temporary plugin. A Keypad binding for `0_0` was saved, but its K1 keydown/keyup were **not observed**; K2/K3 were not verified. The retained evidence does not establish which Working/Task-mode combinations deliver dedicated Task keys. Ordinary Working-mode configurable action slots and firmware/Studio-reserved Task controls must not be treated as equivalent. If Studio exposes a real keyDown/keyUp action binding, bind it explicitly and validate physical input in that mode. If dedicated Task keys are reserved/not dispatched, this package cannot make them work and deliberately has no arbitrary-shortcut workaround. `run` is acknowledged but never fabricated into keydown/up; hold semantics require actual callbacks.

## Protocol and security

- Official main hello: `{code:0,cmd:'connected',uuid:<own UUID>}`. Actions dispatch `keydown`, `keyup`, `dialdown`, `dialup`, `dialrotate`; `key`, `actionid`, and `rotateEvent` are top-level. Callback methods are `onKeyDown(data)`, `onKeyUp(data)`, `onDialDown(data)`, `onDialUp(data)`, `dialRotate(data)`. Only `left` and `right` are accepted; no held-rotation speculation.
- Fixed events: `k1.down/up`, `k2.down/up`, `k3.down/up`, `knob.down/up`, `left.pulse`, `right.pulse`. Owner, session nonce (not real session ID), producer identity, generation, epoch, sequence, timestamp, exact action ID and coordinate are fenced. Unknown fields and settings are not forwarded. Queue is bounded; events older than 1200ms are discarded.
- Dedicated HTTP bridge accepts only POST `/lease`, `/events` and `/bindings` (metadata discovery only, separate capability), exact Host and fixed Origin `dsh-studio-input://com.abworks.ulanzistudio.dshinput`, separate Bearer capabilities, <=4096-byte bodies and bounded requests/bytes. The Node SDK service explicitly supplies that Origin; browser `null` is **not** allowlisted. No ambient cookies, CORS, public address, redirects or arbitrary endpoints. Plugin lease reads cannot renew the owner lease. Server closes when lease expires or canRun fails.
- Producer serializes down/up without losing a fast up while the HTTP down is pending. Failed/stale/overflowed submissions invalidate that run until a new owner generation/epoch, rather than replaying it. Producer never reconnects Studio automatically. Listener status means `listening`, not device-connected; `producerSeen` means a capability holder read a lease, not physical button verification.

## Local build

`node build.cjs` creates `bundle/com.abworks.dshinput.ulanziPlugin` and a SHA-256 inventory, refusing to overwrite an existing bundle. Explicit `--refresh` rebuilds only after every existing bundled file matches the previous inventory and no unknown files (especially pairing credentials) exist. Its `manifest.json` is at the official plugin-folder root. The optional one-time `--vendor-source <reviewed local ws 8.18.0 directory>` copies the retained public dependency; it performs no network/install scripts. The source includes the MIT-licensed dependency for a self-contained Studio Node20 bundle. A ZIP importer format/live installation is not validated by these offline tests.

Historical source contract: public UlanziDeckPlugin-SDK commit `550ab80c69285ecf259bd494a7fff767c14f0c0f`, SDK `ulanziApi.js` callback registration at lines 741–868 and own successful retained temporary-plugin wire implementation. No network research was performed for this delivery.
